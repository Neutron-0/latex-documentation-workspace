\section{Cryptographic Structures}
\label{app-sec:wdb-crypto}

The hash chain and Merkle tree specifications are detailed in \Cref{ch:wolverinedb}. The recurrence relation for the continuous hash chain (\texttt{WDB-0003}) is:
\begin{equation}
    H_i = \text{SHA256}\left( H_{i-1} \parallel \text{SHA256}(m_i) \right)
\end{equation}
Where $H_0$ is the genesis hash (all zeros) and $m_i$ is the deterministic canonical JSON serialization of the $i$-th record payload.

The RFC~6962-compatible Merkle tree (\texttt{WDB-0004}) computes:
\begin{align}
    H_{\text{leaf}} &= \text{SHA256}(0\texttt{x00} \parallel \text{data}) \\
    H_{\text{node}} &= \text{SHA256}(0\texttt{x01} \parallel H_{\text{left}} \parallel H_{\text{right}})
\end{align}

\section{Simulation Boundaries}
\label{app-sec:wdb-sim-boundaries}

Three critical subsystems operate in simulation mode (\Cref{ch:wolverinedb}):

\begin{enumerate}
    \item \textbf{Network Transport} (\texttt{WDB-0100}): The \texttt{DirectMemoryNetworkTransport} passes messages within the V8 heap. It experiences zero latency, zero packet loss, and zero partitions. Claims of BFT resilience based on this implementation are invalid for production contexts.
    
    \item \textbf{KMS/HSM Signing} (\texttt{WDB-0040}): The prototype uses \texttt{LocalSoftwareSigningProvider} with ephemeral keys. The \texttt{CloudKmsSigningProvider} and \texttt{HsmSigningProvider} interfaces exist but delegate to simulated backends.
    
    \item \textbf{EVM Anchoring} (\texttt{WDB-0021}): Checkpoint anchoring targets an in-memory \texttt{Map} rather than a real Ethereum contract. No decentralized persistence is achieved.
\end{enumerate}

\section{Verified Security Vulnerabilities}
\label{app-sec:wdb-vulnerabilities}

The gap between specification and implementation yields known vulnerabilities documented in \Cref{ch:security-ethics}:
\begin{enumerate}
    \item \textbf{In-Memory Transport Collapse:} A single process OOM event destroys the entire ``quorum.''
    \item \textbf{Configuration-Dependent Replay Protection:} CLI runners default to \texttt{InMemoryReplayStore} unless explicitly configured to use \texttt{PostgresReplayStore}.
    \item \textbf{Sentinel TOCTOU Window:} Policy checks occur before ledger append, creating a narrow race condition.
    \item \textbf{No Certificate Pinning:} The simulated transport does not validate peer identities.
\end{enumerate}

\section{Test Coverage}
\label{app-sec:wdb-testing}

The repository contains 219+ vitest test cases covering:
\begin{itemize}[nosep]
    \item Cryptographic primitive correctness (hash chains, Merkle proofs)
    \item Concurrent BFT consensus under contention
    \item Catastrophic recovery scenarios
    \item Database adapter compliance (SQLite, MySQL)
    \item Malicious actor simulation (Byzantine validators)
    \item Fuzzing edge cases
\end{itemize}

\textbf{Critical interpretation:} These tests evaluate \textit{specification compliance under ideal conditions}. A passing consensus test proves that the in-memory event bus functions correctly; it provides zero evidence that the logic survives real TCP/IP network partitions, clock skew, or partial connectivity.
