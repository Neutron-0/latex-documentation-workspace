\section{Entity-Relationship Summary}
The core workflow is driven by the \texttt{Source} entity, which establishes the platforms to be monitored. A \texttt{CollectionRun} represents an invocation against a \texttt{Source} and yields multiple \texttt{Capture} entities. Each \texttt{Capture} acts as a pointer to raw payloads in MinIO. 

Successfully parsed \texttt{Capture} instances map exactly one-to-one to a \texttt{NormalizedRecord} (often referred to as a Canonical Record). If parsing fails, the system bypasses this and creates a \texttt{Quarantine} entity referencing the failed \texttt{Capture}. 

The \texttt{ResolutionCandidate} links two \texttt{NormalizedRecord} entities together for identity resolution, storing similarity metrics and human-in-the-loop audit data. Concurrently, normalized data populates the graph topology, where \texttt{GraphNode} entities wrap \texttt{NormalizedRecord} entities and are connected via \texttt{GraphEdge} relations representing semantic linkages (such as `authored` or `replied`). 

Finally, the \texttt{Outbox} and \texttt{ProcessedMessage} entities are infrastructural, managing transactional outbox patterns for domain event publishing and idempotency across asynchronous messaging queues.
